# Архитектура Istighfar

Документ фиксирует решения, которые отличаются от буквального текста технического задания или влияют на сопровождение.

## Семья не назначается при регистрации

`User.familyId` может быть пустым до создания семьи или входа по приглашению. Клиент не передаёт `familyId`: схема регистрации строгая и отклоняет неизвестные поля. Присоединение возможно только по одноразовому токену приглашения.

В семье не больше двух пользователей. Создание второго приглашения помечает предыдущее неиспользованное как потраченное. Срок задаётся `INVITE_TTL_HOURS`. В базе хранится SHA-256 токена, сам токен возвращается один раз.

## Общий прогресс считается запросом

Отдельного счётчика семьи в базе нет. `GET /family/progress` и `GET /progress/history` суммируют `daily_progress` участников семьи. В эти ответы не входят имена, идентификаторы пользователей и индивидуальные количества.

К ответу прогресса добавлены `remainingCount` и `goalReached`. Они выводятся из той же суммы и цели, отдельных персональных данных не добавляют.

`GET /progress/today` возвращает только запись текущего пользователя. `userId` берётся из JWT. Идентификатор из тела или query не принимается.

## Дата и правки

«Сегодня» определяется часовым поясом семьи через `Intl`. В PostgreSQL дата хранится как `DATE`. Создать или изменить запись можно только за этот день. Чужую запись сервис не находит: условие выборки включает и `id`, и `userId`, поэтому ответ для чужой записи — 404.

Количество — целое от 0 до 100 000. Верхняя граница продублирована ограничением `CHECK` в SQL. Prisma 7 не описывает `CHECK` в схеме и не удаляет его при миграциях, поэтому ограничение живёт в SQL миграции.

## Сессия

Access token живёт в памяти вкладки, срок по умолчанию 15 минут. Refresh token — случайная строка в cookie `istighfar_refresh`: `HttpOnly`, путь `/auth`, `SameSite` и `Secure` из окружения. В базе хранится хеш.

При обновлении выпускается новый refresh token. Повторно предъявленный отозванный токен вне окна 60 секунд отзывает активные токены пользователя. Отзыв фиксируется до выброса ошибки: исключение внутри транзакции Prisma откатывает отзыв. Повтор внутри окна не отзывает новую сессию, но и не выдаёт новый access token, поэтому браузер должен отправить cookie из первого ответа. На клиенте одновременные вызовы обновления схлопываются в один запрос: иначе повторный запуск эффекта в React Strict Mode сжигает токен и сразу показывает экран входа.

Пароли хеширует bcryptjs. Число раундов задаёт `BCRYPT_ROUNDS`.

## Почему Prisma 7 и TypeScript 5.9

Клиент Prisma 7.10 подключается через `@prisma/adapter-pg`. URL базы находится в `apps/api/prisma.config.ts`, не в `schema.prisma`. Каталог клиента — `apps/api/src/generated` — в `.gitignore`.

Линия Prisma 8 на момент разработки была release candidate с другим CLI. В зависимостях зафиксирована 7-я линия.

TypeScript 5.9.3 нужен Nest CLI и тестам: актуальный TypeScript 7 не отдаёт compiler API, на котором собран Nest CLI.

Интеграционные тесты запускает встроенный test runner Node по собранному `dist`. Jest 30 на Node 22 не загружает ESM-пакет `@nestjs/testing`.

## Frontend

Запросы идут через один клиент в `apps/web/src/lib/api.ts`. При 401 он один раз вызывает `/auth/refresh` и повторяет запрос. Токены в `localStorage` не пишутся. Приглашение до регистрации хранится в `sessionStorage`.

Страница истории подгружается отдельно, потому что график Recharts тяжёлый для первого экрана.

Service worker, который генерирует vite-plugin-pwa, кладёт в precache статику сборки. Навигационный fallback не применяется к `/auth`, `/family`, `/progress` и `/health`. Отдельного runtime-кэша API нет.

## Что сознательно не сделано

Нет рейтингов, серий, сравнения супругов и редактирования цели. Недельная и месячная статистика могут строиться по уже существующей истории дней без изменения приватного контракта API.
